## Scope esteso: perché abbiamo migrato anche `io::handle_output`

I 5 testcase byte-aware su `%s`/`%c`/format string/sprintf/print(OFS=`\xC3`) sono **integration test end-to-end via stdout**: leggono `child.wait_with_output().stdout` come `Vec<u8>` e fanno assertion byte-exact. Pre-migrazione di `io::handle_output`, il path `Statement::Printf` e `Statement::Print` passavano `&String::from_utf8_lossy(&output)` a `handle_output(output: &str)` — il `from_utf8_lossy` collassava qualunque byte alto (0xC3 → U+FFFD = `[0xEF, 0xBF, 0xBD]`) **prima** di toccare stdout. Risultato: i 5 RED test continuavano a vedere `[0xEF, 0xBF, 0xBD, …]` anche dopo aver migrato `awk_sprintf` a `Vec<u8>` byte-clean.

Decisione: estendere lo scope di 7.5 a includere la migrazione di `io::handle_output(&[u8])` con `write_all`. Costa 1 funzione (~20 righe modificate in `io.rs`) ma chiude il loop end-to-end e di fatto completa anche il primo dei 2 BRIDGE 7.6 (`output byte-esatto nel path stdout/file/pipe`). Resta solo il BRIDGE 7.6 su `Display` impl di `AwkValue` (types.rs:206) — il `Display` non è più sul path output AWK (lo era prima via `{}` formatter in `print!`/`write!`), serve solo a debug/`{:?}` da Rust. Phase 7.6 sarà quindi probabilmente molto piccola (sola eliminazione del trait Display lossy o sostituzione con `as_string()`).

## Cambi architetturali

- `awk_sprintf` firma: `(fmt: &str, args: &[AwkValue]) -> String` → `(fmt: &[u8], args: &[AwkValue]) -> Vec<u8>`. Parser byte-by-byte: itera `fmt.iter()`, accumula spec (% + flags + width + .precision + conversion byte), delega a `sprintf::sprintf!` per conversion numeriche (ASCII puro) e gestisce `%s`/`%c` byte-aware in proprio.
- `%c`: emette il **primo byte raw** dell'argomento stringa (non `chars().next()` che collassa byte alti su U+FFFD = 3 byte UTF-8).
- `%s`: emette `arg.as_string()` integro come bytes raw. Width/precision applicati **byte-aware** (precision tronca a N byte, width padda a N byte con SPACE o `0`).
- Parser dedicato `parse_s_flags` per width/precision/alignment dello spec `%s`.
- `as_string_convfmt`: firma `(&self, fmt: &str) -> Vec<u8>` → `(&self, fmt: &[u8]) -> Vec<u8>`. CONVFMT/OFMT (`Vec<u8>` in `EvalContext`) passati direttamente; fallback `"%.6g"` interno se l'utente setta CONVFMT con byte non-UTF-8 (POSIX undefined).
- `EvalContext::update_record`: field splitter byte-aware. FS = `b" "` → run di whitespace (`b' '`, `b'\t'`, `b'\n'`) con leading/trailing skip (semantica POSIX awk). FS arbitrario → `split_bytes_by_separator(line, &fs)` helper, substring match byte-exact.
- `io::handle_output`: firma `(output: &str, …)` → `(output: &[u8], …)`. `print!("{output}")` → `stdout().lock().write_all(output)`. `write!(stream.writer(), "{output}")` → `stream.writer().write_all(output)`. Path filename redirect resta `String` (design R3).

## Test additivi (`tests/bytes_printf.rs`, 6 testcase)

1. `printf_s_preserves_high_byte` — `printf "%s\n", $0` con stdin `\xC3foo` → output `\xC3foo\n`.
2. `printf_c_emits_first_byte_raw` — `BEGIN { printf "%c", "\xC3X" }` → output `\xC3` (singolo byte).
3. `printf_format_string_with_high_bytes` — `BEGIN { printf "\xC3%s\n", "x" }` → output `\xC3x\n`.
4. `sprintf_high_byte_round_trip` — `BEGIN { s = sprintf("%s", "\xC3foo"); printf "%s", s }` → output `\xC3foo`.
5. `print_with_high_byte_ofs` — `BEGIN { OFS = "\xC3" } { print $1, $2 }` con stdin `aa bb` → output `aa\xC3bb\n`.
6. `field_split_with_high_byte_fs` — `BEGIN { FS = "\xC3" } { print NF, $1, $2, $3 }` con stdin `aaa\xC3bbb\xC3ccc` → output `3 aaa bbb ccc`. (Pre-7.5 questo passava per coincidenza — doppia lossy su line e fs collassa entrambi a U+FFFD e split produce 3 segmenti. Post-7.5 è byte-clean by-design.)
